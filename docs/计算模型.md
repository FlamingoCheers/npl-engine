# NPL 计算模型（v0.6，从 M1–M4 与 v0.2 实现沉淀，含 2026-08-29 世界机讨论定稿）

> 对应 `项目规划.md` §2。本文描述**已实现**的字段级语义；源码为权威。

## 第一原则

> Narrative Runtime is the source of truth; prose is only a projection.
> （叙事运行时才是真实，小说文本只是它的一次投影。）

```
text(t) = Render(narrative_state(t), scene(t), pov, style)
```

文本不是被"写"出来的，是从运行时状态**渲染**出来的。

## 运行时状态（`src/npl/runtime/state.py: RuntimeState`）

四张表（对应规划 §2 六状态的 v0.3 投影）：

| 表 | 字段 | 对应规划概念 |
|---|---|---|
| `world` | `facts{id→bool}` `locations[]` `time` `entities{}` | World State（上帝视角真相）|
| `characters{name→…}` | `knows[] believes[] suspects{name→conf} does_not_know[] intends[] goals[] personality{trait→score} emotion{dim→score} arc{states,current} believes_about{holder→{knows,does_not_know,believes}} hides[] relations{target→{att→val}} relation_reasons{target→{att→reason}}` | Character State + Epistemic State（个体视角，含嵌套认知）|
| `information{id→…}` | `truth(锚点事实id) holders[] suspected_by{name→confidence} public` | Information Object（信息一等公民）|
| `narrative` | `reader_knows[] conceal_active[] revealed[] suspicions[] unanswered_questions[]` | Narrative State（Reader Model）|

- `believes` 是**命题 id 列表**；命题为真为假由 `world.facts` 接地：
  接地且 false → 虚假信念；接地且 true → 与真相一致；未接地 → 真值未知（NAR-041 提示）。
- `believes_about[H]` 是**嵌套认知**（M3）：`该人物相信 H 知道/不知道/相信某命题`。
  `inspect` 对照 H 的实际认知标注：虚假嵌套信念 / 与事实一致 / 真值未知。
- `hides[]`（M3）：人物主动隐瞒的事实。隐藏者必然知道所隐之事。
- `relations`（v0.5）：有向态度 `(主体,目标,态度)→数值[-1,1]`，行尾注释作为**缘由**一并存储
  （`relation_reasons`）。参照 CK2 修饰符堆叠模式：每条态度独立、带理由、绝对置值，
  `relation_changes` 指令在幕执行时置值并同步缘由，`changes.relations_set` 记录审计轨迹。
  态度进入渲染上下文（影响语气与行为细节，禁止数值入叙述）与 `inspect`/`branch-diff` 输出。
- 序列化 `to_dict()` 全键排序 → 同一程序任意两次模拟输出**逐字节一致**。

## 状态转换（`src/npl/runtime/executor.py: simulate`）

逐幕执行，每幕产出三元组 `(snapshot, ir, changes)`：

- **`information_changes` 全量驱动状态转换**；`events` 是叙事节拍，但其中的
  HIDE / SUSPECT 动作仍分发（隐瞒与起疑天然是读者可见的行为）。
- 动词语义（动词即状态转换指令，M3 全表）：
  - CONFIRM 类 `confirms/discovers/learns/realizes/remembers/infers/notices/finds`：
    `Actor.knows += arg`；arg 为嵌套形式 `B.knows(x)` 时进入 `believes_about[B].knows`
  - REVEAL 类 `reveals/tells/admits/confesses/discloses`：在场者 `knows += arg`
  - MISUNDERSTAND 类 `misunderstands/mistakes`：`Actor.believes += arg`（常形成虚假信念）
  - SUSPECT 类 `suspects/doubts`：`Actor.suspects[arg] = max(旧, 0.5)`
  - HIDE 类 `hides/conceals/withholds`：`Actor.hides += arg`
- `dramatic_goal` → Reader Model：`reveal` → `reader_knows += id` 并解除同目标 conceal；
  `conceal` → `conceal_active += truth锚点`（已揭示的目标不再回退）。
- 闪回场景（`flashback = true`）：状态仍按叙事顺序演化；world_time 仅作标记。
  时间倒叙 = 场景声明顺序 ≠ world_time 顺序，Runtime 不做重排。

## Reader Model（M3）

`narrative` 三条读者轨迹：

- `reader_knows[]`：读者已知（reveal 达成即写入）。
- `suspicions[]`：读者怀疑 = 全部角色的 suspects 并集 + 观察到的隐瞒行为
  （角色 `hides` 且被本幕 POV 观察 → 读者知道"TA 在隐瞒什么"，但不知道内容）。
- `unanswered_questions[]`：悬念清单——conceal 生成"X 的真相尚未揭示"式问题；
  reveal 达成时自动回收含该目标的问题。

```
悬置 = conceal_active ∩ world.facts 且 ∉ 任一 reader_knows 锚点
```

reveal/conceal 因此是**可计算**的叙事操作，而非作者手感。
`npl inspect --reader` 输出读者视角三清单；`--scene N` 可查任意时点。

## 章节意图（v0.5）

顶层 `intent` 块把"作者对整章的验收标准"写成机器可读程序，`npl simulate` 末尾
`evaluate_intents(program, result)` 对照 Reader Model 轨迹检查：

| 指令 | 语义 | 违背 |
|---|---|---|
| `goal = fact` | 章末 `reader_knows` 必须含 fact | NAR-071 WARNING |
| `forbid = fact` | 任何一幕的 `reader_knows` 都不得含 fact | NAR-072 WARNING（报首现幕） |
| `pacing = suspicion_up (fact)` | 该 fact 全员最大 suspects 置信度逐幕单调不减 | NAR-073 WARNING（报回落幕） |

- 检查发生在**状态层**（Reader Model 快照序列），与散文渲染完全解耦——散文由
  `npl check` 单独审计，意图由 simulate 单独审计。
- pacing 当前恒满足（suspect() 取最大值），为未来置信度衰减/反转动词预留语义位。
- `npl continue` 续跑不做意图检查（意图属于整章，续跑是章节间的操作）。

## 关系系统（v0.5）

- 状态：`characters[A].relations[B][att] = v`（-1~1），缘由存 `relation_reasons`。
- 指令：scene 块 `relation_changes { A -> B : att = v }`，**绝对置值**（非增量——
  幕与幕之间没有"当前值"的隐式语义，作者声明每幕结束时的态度终值），带缘由时同步缘由。
- 传播：态度**不**自动改变认知或读者状态（相关性非因果）；它只通过渲染上下文影响
  LLM 的笔触（语气、称呼、回避什么）。这是有意收窄：态度的叙事效果属于投影层。
- 审计：`changes.relations_set`；`inspect` 显示 `目标.态度 = v（缘由）`；
  `npl diff` 输出 `A->B.att: v1 -> v2`。

## 文学原语的运行时语义（M4）

- **母题**（motif）：`narrative.motifs[motif] = [{role, scene}]` 按幂序追加（幂等——同幕同母题
  重复声明只记一次）。三幕结构 `introduce → recurrence → final` 由校验器静态把关（NAR-061/062/063），
  呈现与否由检查器对渲染散文的 `motif_mentions` 抽取对照（NAR-064）。母题是**跨幕的读者情感装置**，
  不进入任何角色的认知状态——它操纵的是 Reader Model 的注意力，不是世界真相。
- **伏笔**（foreshadow）：纯静态声明 + 结构检查（NAR-065）。语义 = "本幕埋，后续幕必须收"，
  收 = 同 target 的 reveal（dramatic_goal 达成）或 CONFIRM/REVEAL 事件。
- **扣留**（withhold）：`target until = N` 在运行时展开为**临时 conceal**——第 i 幕起
  `conceal_active += target`，第 N 幕执行前释放（reveal_to_all 同样解除）。因此 withhold
  与 dramatic_goal conceal 共享同一条"悬置"计算与同一套 031 泄漏检查：扣留期间渲染若说破
  target，检查器照样报 NAR-031。到期未释放 → NAR-066（对 render 产物校验）。
- **误导**（misdirect）：`misdirects_active += target` 并注入 Reader Model 的 suspicions
  （"读者被引导怀疑 X"）；同 target 的 reveal 达成时解除（反转时刻）。
  结构检查（NAR-067）：目标为真事实 → "误导读者相信真相"；后续无 reveal → "无反转载体"。

四者共用一个原则：**作者意图进入 state，可查询、可校验、泄漏可判**——叙事技巧从"手感"变成程序语义。

## 风格系统（M4）

```
预设（STYLE_PRESETS：default / restrained_literary / lush_emotion）
  + 顶层 style 块覆写（desc / sentence_max / emotion_naming / sensory / dialogue_gaps / rule）
  → resolve_style(name, style_decls)  → ctx["style"]（规则文本 + constraints 字典）
  → 渲染 prompt 注入风格段；Constraints 交给检查器（NAR-052 句长抽查）
```

- 风格是**纯渲染层属性**：不改变 IR、不改变认知状态、不改变信息边界（铁律优先于一切文学效果）。
- 同一 Scene IR 换 `style` 即得到可盲评区分的双版本（`experiments/blind_eval/`）。
- 语料风格指纹接口预留：`style/rules.py: corpus_fingerprint`（v0.2：从既有作品统计句长分布、
  比喻密度、情绪命名频率，自动生成 style 块）。

## Actor 模式（M3，可选）

`npl actor <file> --scene N --character C`：角色决策在 epistemic sandbox 内生成——

1. 取本幕开始前的状态快照，`compile_actor_context` 为角色 C 编译**只有 C 能看到**的上下文；
2. prompt 要求输出 JSON 行动提案 `[{action, args, reason}]`（reveal 目标→可感知行动，
   conceal 目标→掩饰行动）；
3. 提案写入 `build/actor_proposals/`，供作者审阅后手动并入场景，或留作 M4 自动汇入。
   这是"角色拥有自己的认知"的雏形：LLM 只看到角色能看到的，提议角色会做的事。

## 认知视角与渲染权限

- `epistemic_view(state, pov)`（`ir/scene_ir.py`）：任意角色在任意时点"知道什么 / 信什么 /
  怀疑什么 / 隐瞒什么 / 对他人认知的建模"。
- `resolve_access`（`executor.py`）：无 `access` 块时的缺省权限——
  POV 的 `perception/memory/inference` 允许；他人的 `private_thought` 与 `world.truth` 拒绝。
- **Context Compiler**（`context/compiler.py`）：deny 的信息**物理上不进入**渲染上下文——
  非 POV 人物只保留 `scene_actions`（外部行为）与 `observable_arc`（外部表现轨迹）。
  LLM 不是"被要求不写"，而是**根本看不到**。这是 NPL 对"AI 知道太多"的结构性解法。
- 检查器闭环（M2）：渲染产物经 LLM 命题抽取 → 规则引擎（NAR-02x/03x）对照认知状态判定泄漏；
  抽取结果按（prompt 版本 + 输入）哈希缓存于 `build/extract_cache/`。

## 渲染管线

```
.npl → parse → validate → simulate（确定性）
     → Scene IR（build_ir，含 reader_model）
      → Context Compiler（权限过滤 + 风格解析 + 母题/误导指令）
      → prompts（铁律 + 指令 + 闪回约束 + 母题指令 + 误导提示）
     → adapter（mock / openai-compatible：DeepSeek/Qwen/智谱/Ollama…）
     → prose（build/prose/scene_XXX.md）
     → check（抽取 → 规则引擎 → NAR 诊断）
```

离线/人工模式：`experiments/dump_ctx.py` 导出每幕权限过滤后的完整 prompt，
渲染与抽取可由人工或外部模型按同一口径完成；`experiments/rejudge_chapter.py`
离线运行规则引擎——整个闭环不依赖在线 API（渲染产物 adapter 标注 `glm-manual`）。

## 多文件程序（v0.2 import）

- `load_program(entry)`：递归收集 import（相对入口文件目录解析），单次包含、
  环检测（NAR-016）、缺失报错（NAR-015）；合并冲突 → NAR-011。
- **场景顺序语义**：合并后 = 导入文件场景（按 import 声明序）在前，入口场景在后；
  叙事的时序/倒叙结构由文件组织表达（序章文件被前置 import 即为倒叙）。
- world 仅入口可声明；render 取入口；母题三幕链跨文件按合并后序列校验。

## 嵌套认知深度（v0.2）

语法支持任意深度（`A believes B knows C.knows(x)`，canonical 化存储于
`state.nested_beliefs`），inspect / prompt 以 `A.believes(B.knows(C.knows(x)))`
形式展示并可做接地标注（与人物实际认知相反 → 虚假嵌套信念）。
**运行时认知转换只验证一层**（事件与 confirm 只展开第一层 holder）——
深层建模是"人物脑内的世界观"，世界引擎不对其递归求真，符合认知逻辑惯例。

### 深层接地验证（v0.3，`inspect --deep`）

`runtime/epistemics.deep_grounding(state, canonical)` 提供可选的逐层接地，
语义为**基础命题近似**（文档与输出均明示）：

- canonical 链上全部是"被建模的他人"，owner 隐式不在链中
  （`老祭司|knows>阿芽|knows>密信存在` = owner 建模
  "老祭司知道阿芽知道密信"）。
- 对每个 `hi|vi`：检查 hi **对基础命题**是否真的持有 vi 态度——
  knows → `prop ∈ hi.knows`；does_not_know → `prop ∉ hi.knows`；
  believes → `prop ∈ hi.believes`。
- 从最内层向外层判定，第一个 violated/unknown 即为总判定锚点
  （`holds / broken:<hi> / unknown:<hi>`），但每层结果完整输出。
- 深度 2 的表达无近似损失；深度 ≥3 的中间层是近似——因为中间人物
  对"复合命题本身"的态度未被建模（只有对基础命题的一层态度）。
- 纯函数、确定性、只在 `inspect --deep` 时启用，不影响默认模拟路径。

## 快照续跑与分支（v0.3）

世界机的状态是纯数据（快照 JSON），因此"续写"与"分叉"不需要特殊机制：

```
npl continue <extra.npl> --from <snapshot.json> [--out DIR]
npl branch-diff <snapA.json> <snapB.json>
```

- `continue`：`RuntimeState.from_dict(快照 state)` 恢复世界 →
  `simulate_continue(state, extra.scenes, 快照幕号 + 1)` 执行追加场景
  （**编号从快照幕号 + 1 续接**，快照本身是"第 N 幕执行后"的状态，
  不重算）。
- 追加程序必须复用基程序的世界与人物（缺人物 → exit 1 拒绝）；
  其 world/character/information 声明仅用于独立校验，不影响恢复的状态。
- `branch-diff`：两条时间线快照的全量状态对比（world facts / 每个人物
  认知、怀疑、隐藏、arc、情绪 / narrative 五字段）。同一快照出发的
  两个分支，差异行就是"分歧点"。
- 确定性不变：同一 state + 同一场景序列 → 逐字节一致的快照。
- 演示：`examples/novel/chapter_extra.npl`（《定金》沉默线）从
  `scene_005` 续跑出第 6 幕，与主线 `scene_005` 的 branch-diff 显示
  分歧（Lin.hides / arc / reader 怀疑与未答之问）。

## 风格指纹（v0.2）

设计目标：**可扩展**——系统拿出去，谁都能用自己的口径写出不同文风的映射。

```
语料(.txt/.md) → build_corpus_stats（一次分词共享）
    → 特征函数表 FEATURES[name](corpus) -> float    ← register_feature 注册，开放
    → 词表 LEXICONS（emotion/metaphor/sensory/punctuations…） ← 整体可注入，开放
    → corpus_fingerprint：{fingerprint_version, feature_set_version, meta, features}
      （json sort_keys 确定性；lexicon_digest 入 meta，口径变化可检测）
    → to_style_decl：确定性映射 sentence_max/emotion_naming/sensory/dialogue_gaps/rules
    → render_style_npl：可直接粘进 .npl 的 style 块
```

- 特征注册：`@register_feature(name, version)`；`feature_set_version` 是
  （特征名, 版本）集合的 sha1——特征集不同，指纹不可比，diff 工具显式提示。
- 词表注入：`corpus_fingerprint(texts, lexicons={...})` 同名类别整体替换、
  新类别透传（供自定义特征消费）；任何团队可带自己的情绪/比喻/感官词表。
- CLI：`npl style fingerprint / show / to-npl / diff`。
- 内置 8 特征：avg_sentence_len、paragraph_len_median、dialogue_ratio、
  emotion_naming_rate、metaphor_density、sensory_density、vocab_richness、
  punctuation_profile（均为每千词/千字归一，跨语料可比）。
- 验收实例：blind_eval A（克制）vs B（浓郁）指纹 diff 与盲评结论一致
  （句长 +11.1 字、比喻密度 +10.6/千词、情绪命名 0 → 2.9、段落中位长 55 → 127）。

## 跨章母题追踪（v0.3）

`src/npl/analysis/tracking.py: track_motifs(chapters, declared, min_scenes, min_total, gap_alert)`
把 v0.2 的单章意象聚类（`imagery.extract_candidates`）升级为长程轨迹视图：

```
每章 → 局部聚类（种子）→ 跨章合并轨迹（label 相同 / 词族相交 / 字符 bigram 相交）
     → 声明匹配（母题 id = label 或 ∈ 词族）
     → series：逐章全文回扫计数（不是"该章是否聚出"）
     → 状态机：活跃 / 收尾 / 间歇 / 断线 + 趋势（前半 vs 后半千字频率）
```

- **全文回扫是关键设计**：某章只出现一次、聚不出局部簇，series 照样计数——
  否则单次出现的章会被误判为断线，预警全是噪声。
- 状态优先级：间歇（中途 gap ≥ 阈值）> 活跃（末章出现）> 断线（声明后
  tail ≥ 阈值）> 收尾。断线与间歇都会给出可操作的告警文案。
- 千字频率 `freq = n / 章字符数 * 1000` 跨章可比；趋势阈值 ±1.3 倍。
- CLI：`npl motifs <章目录...> [--gap-alert N] [--json]`（传 .npl 文件则仍是
  v0.2 单章聚类模式）。章目录约定：顶层一个 .npl + `build/prose/scene_XXX.md`。
- 定位：分析工具，不进语法、不影响确定性；声明信息来自 scene.motifs，
  报告回答三个问题——"我声明的母题是否还在呼吸？哪里断线了？哪条未声明的
  意象线自己长成了母题？"

## 两条时间线（2026-08-29 讨论定稿）

系统里存在两条不同性质的时间线，分离是刻意的：

- **世界时间线（world timeline）**：机器内部、唯一、按 `world_time` 单线演化。
  simulate 的快照序列就是它的运行轨迹（trace）。确定性保证同一程序单次运行
  只有唯一一条时间线；多条时间线只能通过快照读档+分叉显式派生（v0.3 `npl continue`）。
- **叙述时间线（narrative timeline）**：读者读到的顺序。它是**程序的一部分，
  由 .npl 作者在编译期声明**——scene 在文件中的排列顺序 = 叙述顺序，
  `world_time` 字段 = 该幕在世界时间线上的位置，`flashback = true` 显式声明
  倒叙关系。渲染层（LLM）**无权决定幕间顺序**，只能遵守。

分工边界：宏观叙述顺序（哪幕先讲）= 作者/程序定，可声明、可校验、确定性；
幕内微观顺序与文字节奏 = 渲染层定，但受信息边界约束、受 `npl check` 事后审计。
幕内的"回忆插叙"属于 POV 已知内容的使用（非全知），检查器已相应适配。
若未来需要"自动重排叙述顺序"，正确的位置是编译期工具（重排 scene 声明后
重跑 simulate 验证），而不是渲染时临场决定。

## 世界动力学与题材包（v0.4 已实现）

世界机分层：**认知层**（CONFIRM/REVEAL/HIDE/MISUNDERSTAND/SUSPECT 族——
只改"谁知道什么"）与**物理层**（v0.4 WORLD 族——改"世界是什么样"）。
物理与认知彻底分离，观察传播显式化：

1. **世界动词族（已实现）**：`主体.sets(事实)` / `主体.clears(事实)` 只改
   `world.facts`，不触碰任何认知；两通道均生效。谁看见、谁起疑由作者
   用 CONFIRM/SUSPECT 显式声明——认知账目哲学：无隐式状态转换。
2. **世界事件主体（已实现）**：主体可为已声明实体（`灵脉.sets(裂痕)`），
   实体无须入 participants；人物主体亦可（物理行为：`老祭司.clears(外泄)`）。
3. **process 声明（已实现）**：多阶段世界进程声明化（阶段 → 标志事实），
   运行时事实仍由 WORLD 族显式驱动；`npl simulate` 末尾按声明序做
   单调性检查（后阶段真而前置未真 → 乱序告警）。三层记忆各归其位：
   进程进展存 world facts、角色获知存各自 knows/suspects、读者被展示的
   痕迹存 Reader Model。
4. **题材包（已实现）**：世界事实/实体/进程装进可 import 的 .npl（不装
   人物、场景、文风），故事首行 `import "包.npl"` 获得整个世界的物理与
   历史。示例 `examples/packs/northern_veins/`。世界机对题材不可知：
   奇幻的火球与科幻的等离子步枪在事实层同构；题材带来的真正扩展点是
   **新信息通道**（读心 = 新 access 语义、预言 = 从未来事实指向现在
   认知的特殊 confirm）。
5. **推演边界**：世界机不会自行推演，只执行声明的指令——结束条件显式
   （场景跑完 / 读档续跑 / 远期候选 `simulate --until` 目标驱动）。
   世界机是引擎不是司机：它保证"怎么走"符合规则，"去哪里"永远由程序决定。

定位结论：NPL = 认知 CPU（指令集 = 动词语义族，规范见 docs/ISA手册.md），
题材 = 在同一台 CPU 上运行的不同程序，题材包 = 程序库。成文质量
（文风/去 AI 味/重写环）是正交的独立系统，以 CLI --json 契约消费本引擎，
不入本仓库。
